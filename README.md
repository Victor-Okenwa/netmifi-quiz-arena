# Netmifi Quiz Arena

> **Netmifi doesn't just tell students who won. It shows them what they need to learn to win next time.**  
> **Learn. Compete. Improve. Earn.**

**Netmifi Quiz Arena** is a real-time competitive academic quiz platform designed for tertiary undergraduate students within the broader **Netmifi** learning and commerce ecosystem. Built for the **Dev3pack Solana Hackathon**, it transforms independent exam preparation into an interactive, measurable, and social competition with optional Solana-powered reward battles.

---

## 🎯 The Core Product Loop

Traditional study tools deliver static materials without helping students test their mastery against peers in real time or diagnose specific topic weaknesses. Netmifi Quiz Arena is built around a closed learning feedback loop:

```text
BATTLE ──► DIAGNOSIS ──► PRACTICE ──► REMATCH
```

1. **Battle**: Students select their university, department, course, and topic to compete in timed, head-to-head academic quiz battles with questions of matched difficulty.
2. **Diagnosis**: Every completed battle generates a structured performance breakdown—accuracy by topic, response time, question-by-question explanations, and weak-area identification.
3. **Practice**: The platform recommends targeted practice drills focused specifically on the topics where the student struggled (e.g., drilling _Recursion_ after missing recursion questions in _Data Structures & Algorithms_).
4. **Rematch**: Students challenge their friend or opponent again to measure real academic improvement over time.

---

## ⚔️ Free Battles vs. Optional Reward Battles

Netmifi Quiz Arena is an **academic product first**, not a wallet-gated crypto app:

- **Free Academic Battles (Core Experience)**:
  - **No cryptocurrency wallet required.** Students sign up with email/password or Google via **Supabase Auth**.
  - Compete for XP, course and campus leaderboard rankings, achievements, and post-battle learning diagnoses.
- **Optional Reward Battles (Solana Devnet Escrow)**:
  - Students who choose to link and verify a Solana wallet can participate in optional staked battles using Solana Devnet SOL.
  - **Winner-Takes-All Model**: Both participants stake the exact same amount into the battle escrow, and the winner claims the full pot (2 × stake).
  - **Preset Stake Badges**: Instead of arbitrary inputs, players pick from curated presets: `0.005`, `0.10`, `0.20`, `0.30`, `0.50`, `0.70`, and `1.00 SOL`.
  - **Live Balance Protection**: The platform checks each participant's Solana wallet balance in real time before creating or joining a reward room, ensuring both players can afford the match.
  - **On-Chain Settlement**: Real Devnet deposits and backend authority settlement transfers with clickable links to Solana Explorer.

## 🔌 Third-Party Integrations & Services

Netmifi Quiz Arena integrates industry-leading infrastructure services for authentication, real-time multiplayer networking, AI-driven content generation, and voice synthesis:

### 1. Supabase (Auth, Realtime & Object Storage)

- **Supabase Auth (`@supabase/ssr`)**:
  - Provides cookie-based, SSR-safe authentication supporting Google OAuth and Email/Password sign-in.
  - Manages student session lifecycles, user tokens, and profile linking to Nigerian universities, departments, and academic levels (100L–500L).
- **Supabase Realtime (WebSockets & Presence)**:
  - Powers low-latency multiplayer coordination on room-specific broadcast channels (`battle:${battleId}`).
  - Broadcasts battle events: `player_joined`, `player_ready`, `countdown_tick`, `battle_started`, `participant_progress`, and `battle_completed`.
  - Tracks live spectator presence and participant connection state without database polling.
- **Supabase Storage (`quiz-audio` Bucket)**:
  - Serves as the persistent CDN for synthesized MP3 voice files generated by ElevenLabs.
  - Hosts question audio narration, countdown soundbites, and winner announcement recordings with public or signed CDN URLs.

### 2. ElevenLabs (Voice Synthesis & Audio Ceremonies)

- Implemented via `@repo/elevenlabs` using the `eleven_multilingual_v2` model and custom voice styling (`DEFAULT_ELEVENLABS_VOICE_ID = "JBFqnCBsd6RMkjVDRZzb"`).
- **Question Narration**:
  - Automatically synthesizes question prompts and multiple-choice options into clear, natural voice audio for immersion and auditory learners.
- **Lobby & Countdown Announcements**:
  - Preloads a shared voice announcement (`"Battle started! Test your wit and conquer the arena. Good luck!"`) during the 20-second lobby countdown for zero-latency, synchronous playback when the battle timer strikes zero.
- **Personalized Winner Ceremonies**:
  - Generates custom audio celebrations at the conclusion of every battle, dynamically announcing the champion, winning score, and course topic.
- **Deterministic SHA-256 Audio Caching**:
  - Enforces `sha256(normalizedText | voiceId | modelId)` hashing. Audio is synthesized once, uploaded to Supabase Storage, and recorded in PostgreSQL (`audio_assets`), preventing redundant API calls and eliminating recurring latency.

### 3. Firecrawl (Question Factory & Academic Ingestion)

- Implemented via `@repo/firecrawl` to power the platform's **Question Factory**.
- **Automated Curriculum Extraction**:
  - Crawls and scrapes university syllabi, lecture notes, textbook references, and open-source curriculum pages into clean, structured Markdown.
- **Server-Side Request Forgery (SSRF) Protection**:
  - Validates all source URLs using strict SSRF guards (`isSafeIngestionUrl` in `@repo/validators`), prohibiting loopback (`127.0.0.1`, `localhost`), link-local (`169.254.x.x`), and internal private network ranges.
- **Heading-Based Content Normalization**:
  - Parses scraped markdown into discrete topic sections based on document hierarchy. These normalized sections feed the AI Question Generator to produce curriculum-aligned multiple-choice questions with verified explanations for reviewer approval.

## ⛓️ Solana Smart Contract & On-Chain Architecture

Netmifi Quiz Arena implements a **hybrid trust model**: high-frequency gameplay (answering questions, anti-cheat time validation, and score calculation) executes off-chain on the backend for zero latency, while financial custody and settlements execute on-chain via Solana Devnet.

### 1. The Escrow Smart Contract (`programs/quiz-arena-escrow`)

The smart contract in `programs/quiz-arena-escrow` is written in Rust for the Solana runtime:

- **Program ID**: `Fg6PaFpoGXkYsidMpWTK6W2BeZ7FEfcYkg476zPFsLnS`
- **Canonical PDA Seeds**:
  - `BattleEscrowState`: `[b"battle", battle_seed]` (stores battle metadata, participant wallets, status, and stake).
  - `BattleVault`: `[b"battle_vault", battle_seed]` (program-controlled lamport vault holding deposited stakes).
- **Escrow State Machine Lifecycle**:
  ```text
  Created ──► Funded ──► Settled
     │           │
     ▼           ▼
  Cancelled   Refunded
  ```
  1. `Created` (Status `0`): Creator deposits their stake amount (`stake_amount`) into the battle vault.
  2. `Funded` (Status `1`): Opponent joins and deposits the identical matching stake, locking `total_pot = 2 * stake_amount`.
  3. `Settled` (Status `2`): Authorized backend settlement authority submits verified match outcome (`CreatorWins`, `OpponentWins`, or `Draw`). Full pot transfers to the winner (or splits 50/50 on a draw).
  4. `Cancelled` (Status `3`): Creator can cancel an unjoined room and reclaim their stake in full.
  5. `Refunded` (Status `4`): Both participants can reclaim deposits if a funded match expires without settlement.

### 2. Solana Packages & Libraries Used

- **`@solana/web3.js` (`^1.98.0`)**:
  - The core Solana SDK used across both web and SDK packages.
  - Handles JSON-RPC communication (`Connection`), transaction creation (`Transaction`), instruction wrapping (`TransactionInstruction`), public keys (`PublicKey`), Ed25519 signing (`Keypair`), and `SystemProgram.transfer` instructions.
- **`@repo/solana` (Internal Workspace Package)**:
  - Custom TypeScript SDK exporting Anchor IDL constants, instruction discriminators, and deterministic PDA derivation functions (`deriveBattleEscrowPda`, `deriveBattleVaultPda`).
  - Contains client-safe instruction builders: `buildCreateBattleInstruction`, `buildJoinBattleInstruction`, `buildCancelBattleInstruction`, and `buildFinalizeBattleInstruction`.
  - Includes Borsh serializers/deserializers for `BattleEscrowState`, custom error decoders (`EscrowError`), and authority keypair parsing.
- **Injected Browser Wallet Integration (`wallet-client.ts`)**:
  - Connects to **Phantom** and **Solflare** (`window.solana`, `window.phantom.solana`, `window.solflare`).
  - Powers real client-side Devnet stake deposits: players approve a `SystemProgram.transfer` directly in their browser extension, and the confirmed transaction signature is submitted to the escrow backend.
- **Ed25519 Cryptographic Verification (`wallet-auth.ts`)**:
  - Provides cryptographic nonce challenge signing via Node's native `node:crypto` with RFC 8410 DER SPKI/PKCS8 wrappers, allowing students to prove ownership of their Solana public key.
  - Powers 1-Click Devnet Demo Wallets for judges and testers without browser extensions.

## 🚀 Getting Started

### 1. Prerequisites

- **Bun** `1.3.2`
- **Node.js** `>=24`
- **Docker** (for local PostgreSQL)
- **Rust & Cargo** (for smart contract tests)
- **Phantom or Solflare** browser extension (for testing on-chain Devnet deposits)

### 2. Environment Setup

Copy the root environment template to `apps/web/.env.local`:

```bash
cp .env.example apps/web/.env.local
```

Populate the required keys in `apps/web/.env.local`:

- `DATABASE_URL` (defaults to local Docker PostgreSQL)
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
- `NEXT_PUBLIC_SOLANA_NETWORK="devnet"`, `NEXT_PUBLIC_SOLANA_RPC_URL="https://api.devnet.solana.com"`
- `SOLANA_PROGRAM_ID="Fg6PaFpoGXkYsidMpWTK6W2BeZ7FEfcYkg476zPFsLnS"`
- `SOLANA_AUTHORITY_SECRET_KEY` (64-byte JSON byte array or base64 keypair for settlement)
- `FIRECRAWL_API_KEY`
- `ELEVENLABS_API_KEY`

### 3. Install & Run

```bash
# Install workspace dependencies
bun install

# Start the development server (http://localhost:3000)
bun run dev

# Run TypeScript typechecking across all workspaces
bun run check-types

# Run unit tests across packages (Solana SDK, Firecrawl SSRF, ElevenLabs)
bun test

# Build all applications and packages
bun run build

# Lint the monorepo
bun run lint
```
